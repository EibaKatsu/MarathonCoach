# ui

## 1. 通常画面の基本方針
- 通常時は中央メッセージを常時表示しない
- 通常時の中央は「目標との差」を最大表示し、その下に「到達予測時間」を小さく表示する
- 通常画面は FR255 のチラ見視認性を最優先し、計器盤型の1画面とする

## 2. 通常画面の配置
- 上段左: 心拍 / CAP心拍
- 上段右: ペース
- 中央大: 目標との差
- 中央小: 到達予測時間
- 下段左: 距離
- 下段右: 経過時間

## 3. 数字と視覚表現
- 心拍 / CAP心拍、ペース、差分秒、予測時間、距離、経過時間は常時見えるようにする
- 数字を読む前に状態が分かるよう、心拍とペースには簡易な視覚表現を添える
- 細かいグラフ、目盛り、常時カード装飾は増やさない

## 4. 中央メッセージ
- 中央メッセージは常時表示しない
- 節目やイベント発生時だけ中央領域を一時的にメッセージ表示へ切り替える
- 表示後は通常の差分秒 + 予測時間へ戻す
- メッセージは 1〜2 行、即読できる長さを優先する

## 5. 中央メッセージを出すイベント
- 補給準備
- 補給
- ペース修正開始
- CAP心拍接近 / 超過
- 回復・安定
- 距離節目
- 終盤の切り替え区間

## 6. イベント優先順位
1. 危険系
2. 補給系
3. 修正開始系
4. 距離節目系
5. 回復 / 応援系

- 高優先イベント表示中は低優先イベントは待機または破棄でよい
- 実装は高優先優先の簡易実装を許容する

## 7. 表示時間と連発防止
- 危険系: 2.5〜3.0秒
- 補給系: 2.5秒
- 節目系: 2.0秒
- 回復 / 応援系: 1.5〜2.0秒
- 危険系は約30秒のクールダウンを目安にする
- 回復 / 応援系は約5分のクールダウンを目安にする
- 距離節目系は同一節目を再表示しない

## 8. 距離節目メッセージ
- 5km、10km、ハーフ通過などの距離節目は検知してよい
- ちょうど節目では出さない
- Garmin標準の距離通知との競合を避けるため、節目通過から約8秒後に表示する
- 高優先イベント表示中は待機し、約20秒以内に出せなければ破棄する

## 9. 実装方針
- 通常時は計器盤型
- 中央メッセージはイベント時のみ
- 差分秒を中央の主役にする
- 予測時間は中央下に小さく併記する
- 距離節目表示は遅延表示にする
- 過剰な状態管理は避け、シンプルに実装する

## 10. 変更後の確認点
- 中央の差分秒が十分大きく読めるか
- 予測時間が小さすぎないか
- 心拍 / CAP とペースが数字と図形の両方で把握しやすいか
- 中央メッセージの頻度が多すぎないか
- 距離節目メッセージが Garmin 標準距離通知と被らないか
- FR255 相当の画面で情報密度が高すぎないか

## 11. 心拍ゲージの描画仕様を固定する
### 11-1. 配置
- 心拍ゲージは時計枠の左上アーチ型で固定する
- 位置は 9時方向から12時方向までの左上クォーターを使う
- 通常の矩形ブロックではなく、画面外周寄りを使う
- 端で切れないよう少し内側にオフセットして描く
- 細線ではなく、チラ見で分かる太さを優先する

### 11-2. アーチの役割分担
- 9時〜11時30分: `0〜100% of capHr`
- 11時30分〜12時: `100〜110% of capHr`
- CAP位置は 11時30分付近で固定する

### 11-3. 描画ルール
- ベースの薄い背景アーチを先に描く
- その上に currentHr に応じた塗りアーチを重ねる
- CAP位置には短いティックを1本入れる
- currentHr が CAP を超えたときは超過領域へ塗りが伸びる
- 110% 超えは 12時位置でクランプする

### 11-4. 比率
- `currentHr / capHr` の比率で描く
- `0.0〜1.0` は 9時〜11時30分
- `1.0〜1.1` は 11時30分〜12時
- `1.1` 超えは 12時で頭打ち

### 11-5. 色
- 90%未満 of capHr: 余裕色
- 90%以上 97%未満: 注意色
- 97%以上 100%未満: 警戒色
- 100%以上: 危険色
- 色だけに依存せず、CAPティックを必ず表示する

### 11-6. 太さと見た目
- アーチ線は十分に太くする
- 細い1px風の線にはしない
- 二重線や細かい目盛りは入れない

### 11-7. 数値表示
- 左上アーチ内側に心拍数値を置く
- `currentHr` を大きく、`/capHr` を一段小さく表示する
- `HR` や `bpm` のラベルは出さない

### 11-8. 実装上の注意
- 角度基準はコード内で明示する
- 9時開始 / 11時30分CAP / 12時上限 の見た目基準を正とする

### 11-9. 変更後に確認したい点
- 左上アーチとして自然に見えるか
- CAPティック位置が直感的か
- 超過時に 11時30分〜12時 の伸びで危険が伝わるか
- `159 /165` が無理なく読めるか
- 中央の差分秒と予測時間を邪魔していないか

## 16. 数値タイポグラフィの優先順位を固定する
- 今回の画面は文字情報の読みやすさを最優先にする
- 数値はできる限り大きく、太く見えるフォントを使う
- 細いラベルや装飾より数値の視認性を優先する
- 真の太字が使えない場合は、一段大きいフォントや太く見える描画を優先する

## 17. 心拍数値の見せ方を変更する
- 左上アーチ内側に `currentHr` を主役として置く
- `/capHr` は補助情報として一段小さくする
- 例: `159 /165`
- `159` が先に目へ入ることを優先する

## 18. 数値全般のフォント優先順位
1. 中央大の目標差
2. 現在心拍
3. ペース
4. 予測時間
5. 距離、経過時間
6. CAP心拍

## 19. ラベル削減ルール
- 心拍: `HR`, `bpm` は出さない
- ペース: `PACE`, `/km` は省略可
- 予測時間: `予測` ラベルは不要なら出さない
- 経過時間: `TIME` ラベル不要
- 差分秒: `差` ラベル不要

## 20. 文字の太さに関するルール
- 使える範囲で最も太く見えるフォントを優先する
- 同じ情報量なら細い大文字より太い中サイズを優先する
- 影や細い装飾は入れない
- 線が細く見えるならフォントサイズを一段上げる方向で調整する

## 21. 各数値の具体表示イメージ
- 左上: `159 /165`
- 右上: `7:14`
- 中央: `+28s`
- 中央下: `1:08`
- 下段左: `5.1km`
- 下段右: `32:32`

## 22. 変更後に確認したい点
- `159` が一瞬で読めるか
- `/165` が補助情報として自然か
- `+28s` が画面の主役になっているか
- `7:14` が右上で十分大きいか
- `1:08` が小さすぎないか
- 下段の距離と経過時間も無理なく読めるか
- ラベル削減で意味が不明になっていないか
