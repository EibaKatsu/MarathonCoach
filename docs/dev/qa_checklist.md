# qa_checklist

公開前 QA を同じ観点で回すための実行用チェックリスト。
シミュレーター固有の確認は `docs/dev/simulator_checklist.md` を併用する。

## 記録ルール
- 記録フォーマット: `ケース名 | 期待結果 | 実測結果 | 判定(OK/NG) | 再現手順 | ログ/動画パス`
- P0 は全件 `OK` が公開条件
- `NG` は回避策または修正 PR を必ず紐付ける

## 2-1. 単体確認

### 設定保存・読込
- 初期値保存後に再起動しても値が保持される
- 距離と目標タイムを変更後、表示へ即時反映される
- 不正値入力時に初期値へ戻る
- `lthr_bpm` の有効値が再起動後も保持される
- `custom_mode_code` の有効値が再起動後も保持される

### 距離別分岐
- `5.0km` で通知と表示が破綻しない
- `10.0km` で短距離向け表示が正しい
- `21.0975km` でハーフ向け表示が正しい
- `42.195km` でフル向け表示が正しい

### 目標タイム境界値
- `02:30:00` で下限境界の計算が正しい
- `05:00:00` で標準ケースの計算が正しい
- `07:00:00` で上限境界の計算が正しい
- 境界外入力を保存できない

### CAP 優先順位
- カスタムコードの `S1〜S5` がすべて有効なら direct CAP が最優先になる
- `lthr_bpm` 指定時は Garmin Zone4 upper anchor より優先される
- `lthr_bpm` が無効なら Garmin Zone4 upper anchor へフォールバックする
- LTHR が取れない場合は `HRR -> MaxHR` の順でフォールバックする
- Garmin 心拍ゾーンが取れる場合は `Zone4上限 x 93/95/97/99/100%` で S1〜S5 の CAP が決まる
- Garmin Zone4 上限が `null` / サイズ不足 / `0以下` / 非数値でもクラッシュせず次のフォールバックへ進む
- direct CAP 使用時は通常係数計算や bias が混ざらない

### カード表示切り替え
- 中央カードが `1段目ラベル + 2段目メッセージ` の2段表示になっている
- 同一状態では毎秒メッセージが切り替わらない
- 状態変化時はラベルとメッセージが即時更新される
- `ja/en` の切替で中央カード文言も切り替わる

### ビープ音
- 通知イベント時に 1 回だけ鳴る
- 連続発火時に過剰ビープにならない
- ビープ非対応機種で無音フォールバックする

## 2-2. 異常系確認

### 心拍が取れないケース
- 心拍値 `null` でもクラッシュしない
- 心拍依存通知を停止し安全表示へ切り替わる
- 心拍復帰後に通常表示へ戻る

### GPS が荒れるケース
- 距離ジャンプ時に異常通知を抑止する
- ペース急変時に直前安定値へフォールバックする
- GPS 復帰後に通常計算へ戻る

### 設定未入力・異常値入力
- 未入力時に初期値で起動できる
- 異常値入力を保存できない
- 次に直す項目が 1 回で分かる

### 通知が多すぎるケース
- 同一種別通知のクールダウンが機能する
- 1 分以内の重複通知を抑止する
- 重要通知だけが残る
- 距離イベントが中央カードを割り込まない

## 2-3. 実走確認

### 通し確認
- 最低 1 回は通しで確認する
- 走行中にクラッシュや表示欠落がない

### 視認性
- 走行中 1 秒で意味が分かる
- 強い日差しや夕方でも主要値が読める

### 通知疲れ
- 通知頻度がストレスにならない
- 重要通知を見逃さない

### レース想定ペース
- レース想定ペースでも表示が追いやすい
- 疲労時でも ACTION の意味が即時に取れる
- 坂の文脈と ACTION の組み合わせが直感に反しない
