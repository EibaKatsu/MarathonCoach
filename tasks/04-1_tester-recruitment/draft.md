## T01 [P0] Xアカウントを作る

- タスク内容:
  - 募集投稿と返信対応に使う公式アカウントを準備する
- 目的:
  - `プロダクト公式 × 中の人あり` の立ち位置を最初から揃え、募集時の信頼感と親近感を両立するため。
- 草案:
  - 立ち位置:
    - アカウントは `レースナビ公式`
    - 温度感は `公式アカウントを中の人が運営している`
    - 主語は普段 `レースナビです`
    - 補足や裏話は `中の人としては` を許容する
  - 表示名案:
    - 第一候補: `レースナビ | Garminレース支援`
    - 第二候補: `レースナビ公式 | Garminレース支援`
    - 第三候補: `レースナビ開発室`
  - 採用案:
    - X の表示名は `レースナビ | Garminレース支援` にする
    - `公式感` は出しつつ、投稿文では `中の人が見ています` を添えて距離を縮める
  - ID方針:
    - X では意味が伝わりやすいIDを優先する
    - 候補: `racenavi_run` `race_navi_app` `racenavi_garmin`
    - 可読性優先で、英数字のみ・短め・意味が伝わるものを採用する
  - アイコン/ヘッダー:
    - アイコンはアプリアイコンを使い、個人アイコンは使わない
    - ヘッダーは `レース中に迷わない` `補給忘れを減らす` `実機テスター募集中` の3要素を載せる
  - 表示名の確定案:
    - `レースナビ | Garminレース支援`
  - プロフィール文案（X）:
    - `Garmin向けマラソン支援 Data Field「レースナビ」の公式アカウント。レース中の迷いを減らす表示と通知を改善中。実機テスター募集中です。`
  - Website欄の案:
    - `公開前`: `Xプロフィールのまま運用`
    - `公開後`: `Connect IQ Store の Race Navi URL`
  - 固定投稿の役割:
    - `何のアカウントか`
    - `誰が運営しているか`
    - `今は何を募集しているか`
    - `DM / BETAストア / 設定方法` の導線
  - 固定ポストの運用メモ:
    - ストア公開後に設定する
    - 公開前は下書きのみ保持し、通常投稿で先に募集を進める
  - 返信方針:
    - 質問には原則24時間以内に返信
    - 不具合報告には `ありがとう + 事象確認 + 次アクション` の順で返す
    - 応募の入口は `リプライまたはDM` にし、配布管理は管理表で行う
  - 注意点:
    - `開発者個人の雑談アカウント` にはしない
    - `会社広報のような無機質な文面` にも寄せすぎない
- 結果:
  - `レースナビ | Garminレース支援` を表示名の採用案とし、運用方針は「アカウントは公式、温度感は中の人が運営」で固定する。

## T02 [P0] 実機テスター募集の目的を明文化する

- タスク内容:
  - 実機テスター募集の目的を明文化する
- 目的:
  - 募集投稿で `何の協力か` と `参加すると何が良いか` が一目で分かる状態を作るため。
- 草案:
  - 募集目的文:
    - `主要機種での実機動作確認に加え、レース本番で迷いを減らせる体験へ改善するために、実機テスターを募集します。`
  - 価値交換の明示:
    - 開発側の価値: `主要機種の確認 / 視認性と通知体験の改善 / 不具合の早期発見`
    - 参加者の価値: `正式公開前に試せる / 改善に意見を反映できる / 継続改善の当事者になれる`
  - 募集で見たいこと:
    - インストールと初回設定で迷わないか
    - 走行中に1秒で意味が分かるか
    - 通知が多すぎないか、少なすぎないか
    - 補給通知が実走で役立つか
    - 機種差分による表示崩れや動作差がないか
  - 想定募集人数:
    - `下限5名 / 目標8名 / 上限10名`
  - 募集時に最初に出す一文:
    - `Garminで走るときの“迷い”を減らすため、実走で試して率直に感想を返してくれる方を募集します。`
  - 注意点:
    - 目的文は応募条件より先に置く
    - `不具合探しだけ` の印象にせず、`体験改善の共創` として伝える
- 結果:
  - 募集目的は `主要機種の実機確認` と `本番で迷わない体験の改善` の2本柱で固定する。

## T03 [P0] 募集対象の条件を決める

- タスク内容:
  - 募集対象の条件を決める
- 目的:
  - 応募後のミスマッチを減らし、短期間で有効なフィードバックを回収するため。
- 草案:
  - 必須条件:
    - 使用機種名を共有できる
    - Connect IQ アプリを使える、または導入に抵抗がない
    - 配布後7日以内に初回フィードバックを返せる
    - 10km以上のラン、またはレース想定の実走確認を1回は行える
  - 歓迎条件:
    - 初フル挑戦者
    - サブ4〜サブ3.5を目指している人
    - Garminは使っているが、レース中の判断や補給にまだ不安がある人
    - 日常ラン中心で、Venu / vivoactive系でも試せる人
  - 対象外に近いケース:
    - 室内トレッドミルのみで確認予定
    - 実走確認が難しく、感想提出の見込みが低い
    - 使用機種が分からない、または共有不可
  - 募集文に入れる条件の見せ方:
    - `必須`
    - `歓迎`
    - `こんな方に合います`
  - 投稿用の短縮条件文:
    - `Garmin利用中 / 10km以上で1回試せる / 7日以内に感想を返せる方`
  - 注意点:
    - 条件を厳しくしすぎず、応募ハードルは低く見せる
    - ただし `初回フィードバック期限` だけは明記して運用負荷を抑える
- 結果:
  - 応募条件は `機種共有` `Connect IQ利用可` `10km以上実走可` `7日以内の初回フィードバック` を必須条件に固定する。

## T04 [P0] 優先的に集めたい機種帯を決める

- タスク内容:
  - 優先的に集めたい機種帯を決める
- 目的:
  - 未検証機種の穴を埋め、公開前の機種差分リスクを下げるため。
- 草案:
  - 優先順位の原則:
    - 第一優先: `自分の未保有機種`
    - 第二優先: `画面サイズや系統が異なるシリーズ`
    - 第三優先: `売れ筋で利用者数が多いシリーズ`
  - 優先機種帯:
    - Forerunner系: `FR165 / FR255 / FR265 / FR965 / FR970`
    - ライフスタイル系: `Venu 3 / vivoactive 5 / vivoactive 6`
    - ハイエンド系: `fēnix 7 / fēnix 8 / epix Pro`
  - 募集管理の単位:
    - まずは `Forerunner` `Venu-vivoactive` `fēnix-epix` の3帯で見る
    - 追加で `型番` も記録し、同シリーズ内差分を追う
  - 機種配分の目標:
    - Forerunner系 `3名`
    - Venu-vivoactive系 `3名`
    - fēnix-epix系 `2名`
  - 不足判定:
    - 各機種帯で `応募1名未満` または `実走フィードバック0件` なら追加募集対象
  - 追加観点:
    - 競技寄りユーザーだけでなく、日常兼用ユーザーも含める
    - 画面サイズ差とUI差の両方を拾う
  - 注意点:
    - `機種数を増やすこと` ではなく `主要差分を埋めること` を優先する
- 結果:
  - 優先機種帯は `Forerunner` `Venu-vivoactive` `fēnix-epix` の3帯で管理し、目標配分は `3 / 3 / 2` とする。

  - X 用の募集文は `短く結論先行、固定ポスト誘導` を基本形にする。

## T06 [P0] X 用の中の人投稿文を作る

- タスク内容:
  - X で募集の空気を温める `中の人投稿` 文面を作る
- 目的:
  - 募集告知だけのアカウントに見せず、改善が進んでいることと運営者の存在を伝えるため。
- 草案:
  - 投稿方針:
    - 1投稿1テーマに絞る
    - `中の人より` で始めてもよい
    - 募集の再告知だけでなく、改善ログとして読める形にする
  - 改善ログ投稿:
    - `中の人より。走っている最中は想像以上に文字を読む余裕がないので、まずは「1秒で意味が分かる表示」に寄せて磨いています。いま実機テスター募集中です。興味ある方はリプライかDMをお願いします。`
  - 進捗共有投稿:
    - `中の人より。実機テストで見たいのは、初回設定で迷わないか、走りながら見やすいか、通知が多すぎないか。この3点です。気になっている方はリプライかDMをどうぞ。`
  - 不足機種向け投稿:
    - `中の人より。次は Venu / vivoactive 系の確認を増やしたいです。普段使い寄りのGarminでもレース中に見やすいかを確かめたいので、該当機種の方がいたらリプライかDMをお願いします。`
  - コメント返信の初動テンプレ:
    - `ありがとうございます。よければDMで機種名だけ送ってください。中の人から流れをご案内します。`
  - 注意点:
    - 個人雑談に寄せすぎない
    - `中の人` は近さを出すために使い、責任の所在は公式アカウント側に置く
- 結果:
  - X では `募集告知` と `中の人投稿` を併用し、募集だけの無機質な運用にしない。

  - デザイン方針:

## T08 [P0] 応募受付方法を決める

- タスク内容:
  - 応募受付方法を決める
- 目的:
  - 配布導線と応募管理導線を分けつつ、運用ミスを防ぐため。
- 草案:
  - 導線の役割分担:
    - `BETAストアURL`: インストール導線
    - `DM / リプライ`: 応募受付と初回ヒアリング
    - `管理表`: テスター登録と進行管理
  - 運用フロー:
    - SNS投稿から `リプライまたはDM` へ誘導
    - 返信で `機種名 / 10km以上で試せるか / 7日以内に感想OKか` を確認する
    - 条件が合う人へ `BETAストアURL` と設定方法を案内する
    - やり取り内容は管理表へ転記する
  - この方式の利点:
    - 4-0の `ストアURL固定` 方針を崩さない
    - 応募ハードルを下げやすい
    - 参加意思のある人とそのまま会話を始められる
  - DM返信テンプレ:
    - `ありがとうございます。もしよければ 1) 機種名 2) 10km以上で1回試せるか 3) 7日以内に感想を返せるか、の3点だけ教えてください。確認後にストアURLと流れをご案内します。`
  - 注意点:
    - 応募条件の確認項目は3つに絞る
    - DMだけで流れが見えなくならないよう、管理表へ当日転記する
- 結果:
  - 受付導線は `DM / リプライ`、配布導線は `BETAストアURL`、進行管理は `管理表` に役割分担する。
