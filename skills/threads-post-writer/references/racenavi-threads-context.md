# RaceNavi Threads Context

## Account Role

- 対象アカウントは、Garmin 向けランニングアプリ `RaceNavi` と `関門ガイド` を個人開発している市民ランナー本人のアカウント。
- 投稿者はエリートランナーではない。実際にレースで迷い、失敗し、Garmin を見ながら試行錯誤している立場を前に出す。
- 完成された宣伝文ではなく、`自分が走って困ったから作っている` `まだ実走しながら直している` という人間味を大事にする。

## Goal

- まず Threads 上で共感、返信、保存、プロフィール訪問を増やす。
- 最終的に RaceNavi、関門ガイド、Web サイト、Connect IQ、note への導線を育てる。
- ただし投稿単体では売り込みを強くしない。

## Analysis Viewpoint

既存投稿を確認するときは、次を短く整理する。

- いいねが多い投稿
- 返信がついている投稿
- インプレッションを取りやすそうな投稿の推定
- 長さ、書き出し、話題、口調、締め方の傾向
- 反応が取りやすい柱:
  - RaceNavi系
  - 関門ガイド系
  - 練習・レース体験系
  - 開発裏話系
- 反応が弱い投稿の共通点
- 説明っぽさの有無
- `それ分かる` と思える具体場面の有無

## Core Posting Rules

- 1 回で 10 件出す。
- RaceNavi と関門ガイドを混ぜる。
- きれいに半々にしなくてよい。
- 投稿は説明ではなく、ランナーの実感から始める。
- 機能紹介より、レース中の困りごと、焦り、判断ミス、あるあるを先に出す。
- 最後に無理な質問を付けない。
- `どうですか？` `あなたはどう思いますか？` のような締めは避ける。
- 本文の中に自然な共感や返信余地を残す。
- 少し軽く、楽しいトーンにする。
- ただしふざけすぎない。
- 宣伝臭を出しすぎない。
- `便利です` `ぜひ使ってください` `おすすめです` などの売り込み表現は避ける。
- 使う側と作る側のズレや、自分で作って自分で文句を言っている感じは使ってよい。
- 机上の開発ではなく、実走して分かったことを重視する。
- レース後半のリアルを入れる。
- Garmin の小さい画面、汗、腕の揺れ、老眼、疲れ、焦り、前半の突っ込み、関門不安を自然に扱う。
- ただし毎回同じ話題にしない。
- アイデア募集は、最後の質問ではなく本文の余白として自然に入れる。

## RaceNavi Themes

- 前半に周りにつられて速く入りすぎる
- レース前は冷静に走るつもりでも、スタートすると忘れる
- 5km、10km では楽に感じてしまう
- 30km 以降に前半の速さがきつくなる
- Garmin にはいろいろ表示できても、後半にそれを見て判断できるとは限らない
- 心拍を普段は見るのに、本番では見ないふりをしがち
- ゴール予測タイムを見ると気持ちが揺れる
- 目標タイムに対して今どうなのかを、疲れていても見やすくしたい
- 走っている最中の自分は、思っているほど冷静ではない
- RaceNavi は `賢いアプリ` というより、後半の余裕がない自分でも使える画面を目指す
- ゴール予測を見ながら、心拍・ペースのバランスを調整できる画面にしたい

## 関門ガイド Themes

- 関門表はレース前には見たつもりでも、走り出すと忘れる
- 次の関門が何km 地点か、何時までか、後半になると怪しくなる
- 完走ぎりぎりのレースでは関門がずっと気になる
- ウルトラではエイド、関門、登り、歩きの判断など考えることが多い
- スマホで関門表を見るのは、走っている最中にはかなり面倒
- スクショを探す、拡大する、今どこか確認する、という作業が後半はしんどい
- Garmin に次の関門までの距離と残り時間が出るだけでも助かる
- Garmin の距離は実際より多めに出ることがあり、表示切り替えにも影響する
- 実際に走ると、机上では分からないズレが出る
- 関門ガイドは公開しながら実走で直している初期フェーズのプロダクトとして扱う
- `β版` という表現は使わない

## Avoid

- `数字` という言い回し
- `請求される` のような変にうまい言い換え
- 体や関門表の擬人化
- `雑になる` のような選び抜いた感が出る言葉
- きれいすぎる比喩
- コピーライターっぽい締め
- 説明資料のような投稿
- 便利機能の羅列
- 最後だけ質問にするアンケート風の締め
- `ランナー必携` `革新的` `最高` `誰でも使うべき`
- `詳しくはこちら` ばかりの投稿
- AI が整えたような短文連発
- かっこよくまとめる一文

## Voice

- 自然な口語
- 少し軽い
- 少し自虐は可
- 走っている人の実感を優先
- 断定しすぎない
- 文章を整えすぎない
- ただし読みにくくはしない
- 一人称は `自分`
- ですます調を多用しすぎない
- 関西弁・京都弁に寄せすぎない
- 投稿者本人が普通に Threads に書いている感じにする

## Structure Pattern

1. レース中や開発中の具体的な場面から入る
2. 自分の失敗、迷い、困りごとを書く
3. RaceNavi または関門ガイドにつながる理由を書く
4. 機能説明は必要最小限にする
5. 最後は軽く余韻を残す
6. 無理に質問で締めない

## Quick Smell Check

- その投稿はランナーの困りごとから始まっているか
- 具体的な場面が 1 つは入っているか
- 宣伝より体験が前に出ているか
- 後半で余裕がない自分を前提にできているか
- 説明資料のように見えないか
