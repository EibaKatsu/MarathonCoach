# RaceNavi Note投稿作成

RaceNavi の note 記事を、体験ベースで重複なく継続できるように作る。

## Quick Flow

1. `references/racenavi-note-editor-profile.md` を読む。
2. note URL (`https://note.com/ebasan`) の既存記事を確認する。
3. 既存記事のテーマ・トーン・重複リスクを整理する。
4. 次テーマ案を 3〜5 個提案する。
5. 選択テーマに対して 3〜6 問ヒアリングする。
6. 回答を受けて 3〜5 問の深掘り質問を行う（2〜3 往復）。
7. 素材が揃ったら、本文前に「狙い / 想定読者 / タイトル3案 / 流れ / 画像挿入位置 / 着地案」を提示する。
8. 本文作成後に STEP 5 の観点で再校正する。
9. 本文は `scripts/save_note_post.sh` で日付ファイル名の md として保存する。

## Step 1: 既存記事の確認

- note URL を確認し、公開されている既存記事を読む。
- 次を整理する:
  - 扱ったテーマ
  - 文体やトーン
  - 既に書いている体験談
  - 今後広げられそうな論点
  - 重複しそうな話題
- 上記を踏まえて、次テーマ案を 3〜5 個提示する。

## Step 2: テーマ選定後のヒアリング

- まず 3〜6 問（番号付き、短く、答えやすく）質問する。
- 回答後、3〜5 問の深掘り質問を行う。
- 必要なら 3 往復目まで行い、体験談・感情・具体場面・数字を引き出す。
- すでに分かっているプロフィール情報を毎回聞き直さない。
- 「短くて大丈夫です」を添える。

## Step 3: 記事設計（本文前）

素材が揃ったら先に以下を出す:

- 記事の狙い
- 想定読者
- タイトル案 3 本
- 記事の流れ
- スクリーンショット挿入位置
- 最後の着地案

## Step 4: 本文作成

- note 向けの Markdown で作成する。
- 1 段落は短め。
- 技術説明より、体験・課題・気づき・作った理由を優先。
- 読み物として自然な流れを優先。
- 必要なら太字候補・画像キャプション候補も提案。

## Step 5: レビュー・再校正

以下の観点で再校正する:

- 同じ意味の繰り返しを削る
- 見出し直後の言い直しを避ける
- 接続詞の使いすぎを避ける
- 抽象説明より具体場面・感覚・迷いを残す
- 「整えすぎ」を避け、普段の言い回しを少し残す
- 売り込みだけテンプレ調にしない
- 重複段落を 1〜2 個削る
- 「この文を口で言えるか」で最終確認する

## Theme Proposal Focus

- レース中の判断の悩み
- 心拍とペースのバランス
- ゴール予測の意味
- RaceNavi 開発で見えたこと
- 市民ランナーの実感
- 実戦で分かった改善点
- フル / ハーフ / トレイルの違い
- 「自分向けに作ったものが他のランナーにも役立つか」

## Output Format

毎回の返答は基本的に次の順:

1. 既存記事の確認結果
2. 次のテーマ案（3〜5 個）
3. おすすめの 1 本と理由
4. まず確認したい質問（3〜6 問）

※ 素材が十分に集まるまでは本文を完成させない。

## Writing Style

- 日本語
- やわらかく、誠実、少し親しみやすく
- 技術寄りにしすぎず、ランナーの実感を主役にする
- 売り込みは強くしすぎない
- 最終出力は見出しつき Markdown

## Do Not

- 推測で体験談を盛る
- いきなり長文完成稿を出す
- 既存記事未確認でテーマを決める
- 同じ話の焼き直し
- 機能一覧だけの記事化
- 「AIがすごい」「技術がすごい」を主役にする

## File Save Rule

- 投稿本文は `content/` 配下に `YYYY-MM-DD.md` 形式で保存する。
- 同日複数稿の場合は `YYYY-MM-DD-2.md` のように連番を付与する。
- 保存は `scripts/save_note_post.sh` を優先して実行する。
